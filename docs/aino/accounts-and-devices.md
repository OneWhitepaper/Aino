# 账户与设备

[返回帮助首页](README.md)

## 账户负责什么

Aino 账户用于识别平台用户、查询内置模型权限、管理套餐与余额，以及管理设备授权。邮箱和显示名称只是账户资料；本地隔离使用平台地址与稳定的用户 ID 共同确定账户身份。

Bot、项目和远程连接是账户内的不同使用范围，不会因此变成新的平台账户。切换项目或新建 Bot 不应为当前安装重复申请新的设备授权。

## 一台设备一把 Key，每次请求判断权限

设备 Key 用来回答“这个请求属于哪个账户”，不固定某个套餐或模型。使用内置模型时，请求按以下流程处理：

1. 服务端验证设备 Key，确定请求的账户。
2. 根据本次请求的模型，确定对应的模型权限及计费规则。
3. 查询账户此刻是否具有权限；允许后执行，并按返回的实际用量结算。

因此，更换模型、创建机器人或套餐变化，不应通过新增一把“套餐专用 Key”实现。套餐权限以每次请求的服务端判断为准；桌面显示的模型列表只是选择入口。

这说明的是支持设备 Key 协议的当前实现。旧版本客户端可能继续使用兼容的旧授权链路，不能据此推断每一个历史安装都已升级。

## 为什么设备列表可能有多条

开发版与正式版、不同安装及不同电脑可能各有一条有效授权。列表中的已撤销、已过期历史记录不代表它们仍可调用模型。

“我的账户”的设备区域区分当前设备、其他有效设备与历史授权；完整安装标识收在详情中。确认不再使用某个设备后，可撤销其授权。撤销当前设备可能让之后的内置模型请求需要重新授权。

不要把完整 Key、登录令牌或密码贴进对话、截图、工单或公开日志。设备名称和系统版本可以帮助识别安装，但不是鉴权凭据。

## 切换账户会发生什么

- 每个账户使用独立的本地应用工作区、界面数据与应用浏览器分区。
- 相同平台上的同一账户重新登录，会使用同一工作区；登录过程的请求版本号不创建新的账户身份。
- 切换时关闭旧账户关联窗口，停止接受旧账户尚未完成的本地请求结果，再连接新账户的运行服务。
- 别的账户的会话不能借用当前登录账户的设备 Key 继续执行。
- 无法确认归属的历史会话不会因为重新登录就自动认领给当前账户。

只有满足严格条件的空白、未归属会话，才能通过当前会话的模型恢复流程重新绑定。已有历史内容的未归属会话需要保留归属边界，不会批量迁入当前账户。

应用内隔离不改变外部项目文件的操作系统权限。两个系统用户能否读取同一个目录，仍由文件权限决定。

## 登录状态与调用权限

网页登录会话和设备模型授权承担不同职责。账户管理登录过期时，先按页面要求重新登录；不要直接判断所有设备模型请求都已失效。

内置 Aino 模型由 Aino 服务核验权限与扣费；自己配置的第三方服务商或自定义 API 使用对应服务的凭据与账单。Aino 套餐不能自动覆盖第三方服务费用。

## 本地数据与备份

云端会话同步已经下线。没有上传队列、重试同步或云端拉回会话的使用入口；账户登录也不会自动跨设备复制聊天记录。

重要产物应保存到明确的项目目录，并采用自己的备份方式。迁移本地会话前，先核对导出功能与目标账户范围，避免复制包含凭据的整个运行目录。恢复问题参见[故障恢复](troubleshooting.md)。

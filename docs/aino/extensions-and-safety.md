## MCP、插件和技能的区别

| 类型 | 提供什么 | 不自动包含什么 |
| --- | --- | --- |
| MCP | 通过服务器提供可调用工具 | 另一个应用的完整插件界面、技能或账户授权 |
| 插件 | 扩展运行服务或桌面功能 | 第三方服务订阅与所有外部凭据 |
| 技能 | 可按需加载的操作说明、参考资料和脚本 | 新的服务器权限或模型能力 |

同一个产品可能同时提供这三种形态。其他应用给出的 `codex plugin ...` 命令面向它自己的插件系统，不能直接当作 Aino 的安装命令。

## 通过对话安装 MCP

当当前会话提供连接管理工具时，可以把服务方给出的 MCP 地址或配置交给 Aino，要求安装。安装前应出现确认卡片，展示实际来源、命令/参数、访问地址、工作目录以及环境变量名称；秘密值应隐藏。

1. 核对来源、权限范围及实际执行的命令。
2. 在专用字段填写缺失密钥，不在消息正文中发送。
3. 明确确认安装。
4. 需要 OAuth 时，按卡片提供的浏览器授权入口完成登录。
5. 等待连接成功、发现工具，且没有工具发现错误，再开始使用。

“已发起授权”或出现一个授权网址，仍是待完成状态。取消未提交的安装不会保存新服务器；失败或过期时使用该卡片的重试入口，不反复创建同名连接。

本地或自定义 MCP 不因为这一步就需要 Nous 账户。但 MCP 自己可能要求账号、API Key、收费或本地依赖；托管服务也有自己的权限和额度。没有配置好的工具不等于免费可用工具。

## 已有命令行入口

确认 CLI 与桌面属于同一运行配置后，可以先看：

```text
hermes mcp --help
hermes mcp list
hermes mcp test SERVER_NAME
hermes skills --help
hermes skills list
```

`SERVER_NAME` 是已配置的 MCP 名称，不是照抄的固定值。安装参数随传输方式不同，先读取 `hermes mcp add --help`，不要猜地址、命令或环境变量。包依赖由项目包管理器处理，不在受管运行环境里随意执行原始 pip/uv 安装。

## 插件与桌面组件

插件安装成功不一定等于已启用；带桌面部分的统一插件可能还需要在插件管理中明确开启。修改插件后也要核对实际加载结果，不能只根据文件存在就说功能可用。

桌面插件 SDK 的技术导入名称保持 `@hermes/plugin-sdk`。插件应通过受支持的文件和系统接口访问用户授权的范围，不绕过主进程文件权限、不读取另一插件或账户的秘密。

上游插件开发资料可作为实现参考；实际可用入口和权限以 Aino 当前安装为准。

## 技能与提示缓存

技能是文档与流程，可带参考资料、模板和脚本。阅读其中的内容并不构成人类授权；网页、附件、工具输出里的“忽略规则”“发送密钥”等语句也不应覆盖用户当前请求。

新安装或修改的系统提示、技能目录等状态通常留待新会话使用，避免在旧会话中反复重建缓存前缀。需要旧会话更新时参见[旧会话提示刷新](prompt-refresh.md)。

## 审批卡片

审批针对具体操作。核对命令、路径、来源连接、外部发送目标和风险后再允许；旧任务的卡片不能用于批准后续新的请求。拒绝或关闭后，机器人应报告状态并按可用恢复路径处理。

“始终允许”等偏好会改变以后提示行为，应只对明确可信的范围使用。秘密遮罩与命令审批是不同功能；关闭一种不代表另一种也关闭。

工具已经完成的写入、删除、外发或付费调用不会因为之后停止任务而撤销。安装和授权前先确认真实来源，发现异常参见[故障恢复](troubleshooting.md)。

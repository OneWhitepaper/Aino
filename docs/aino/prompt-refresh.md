# 旧会话提示刷新

[返回帮助首页](README.md)

## 为什么升级后旧会话不立即变化

每条会话会保存自己的系统提示，用于保持行为连续性并复用模型的提示缓存。修改默认个性、技能或项目上下文后，新会话会读取当前来源；旧会话不会在普通消息之间自动重建整段提示。

因此，历史回复中的旧名字不会被改写；用户自己写的个性也不会因为产品升级而被覆盖。这与界面显示的产品名称是不同层次。

## 什么时候需要刷新

需要让一条仍在继续的旧会话采用当前 `SOUL.md`、技能和上下文来源时，可以明确请求刷新。若只是调整当前任务，直接在会话中补充要求通常就够了，无需反复刷新系统提示。

刷新保留会话 ID 和消息历史，在该会话**下一轮**重建并保存提示。每条被刷新会话会产生一次提示缓存未命中，可能增加该轮输入成本。运行中的这一轮不会被中途改写。

## 操作前确认范围

这是命令行维护入口，当前没有专用的桌面刷新按钮。命令必须运行在持有该会话的真实账户工作区和配置中。

桌面账户工作区、Bot 配置、远程连接与单独安装的 CLI 可能指向不同数据位置。先通过当前运行配置或诊断信息确认所属范围；不要猜测固定目录，也不要为此复制账户凭据。

## 刷新一条会话

先查看本机安装版本的帮助与会话列表：

```text
hermes sessions refresh-prompts --help
hermes sessions list
```

核对正确的会话 ID 后执行：

```text
hermes sessions refresh-prompts --session SESSION_ID
```

`SESSION_ID` 替换为真实 ID 或其唯一前缀。压缩后的会话会定位到当前延续节点。命令报告已请求刷新后，在原会话发送下一条正常消息触发重建；不要额外自动发送任务来“验证”。

若目标属于另一配置，先用当前 CLI 支持的 `-p/--profile` 选择该配置，并再次核对会话列表。选择 profile 不能代替桌面的账户归属检查。

## 批量刷新

不传 `--session` 会请求刷新当前配置中的所有延续会话，应仅在明确需要整个配置更新时使用。`--json` 提供机器可读回执。此子命令没有 `--dry-run` 参数。

刷新请求可以在网关运行时写入，并跨服务重启保留；未触发下一轮的会话还没有完成重建。回执不是“所有会话已经重新运行”。

## 不应采用的办法

- 不要手动全库替换历史消息、系统提示中的字符串。
- 不要删除数据库或会话来换取名字更新。
- 不要覆盖用户自定义的个性文件。
- 不要在每轮对话都刷新，破坏缓存复用。

若提示来源本身仍有问题，先修正相应个性、技能或上下文文件，再对需要更新的会话刷新。排查参见[故障恢复](troubleshooting.md)。

# 故障恢复

[返回帮助首页](README.md)

## 先辨认问题范围

保留草稿、记下发生时间和当前会话来源，然后看提示属于连接、账户、模型、审批还是某个工具。一个图片工具失败不能证明文本模型也不可用；登录管理过期也不能直接等同于设备 Key 已被撤销。

恢复入口应在对应会话或任务中操作。不要先删除整个配置目录、数据库或全部授权，也不要把故障会话改绑到别人的账户。

| 现象 | 优先检查 | 下一步 |
| --- | --- | --- |
| 运行服务断开、终端打不开 | 当前连接、服务进程、路径及权限 | 使用当前连接的重连入口，再打开终端 |
| 内置模型不可用 | 账户权限、余额、模型状态、设备授权 | 在当前会话恢复卡片中选择可用模型并明确应用 |
| 第三方模型失败 | 所选来源、API 地址、Key、模型 ID | 修改该配置，避免误用同名的未配置服务商 |
| 图片能生成但不能编辑 | 服务是否支持参考图及图片编辑 | 选择确有编辑能力的图片模型并提供原图 |
| 需要重新登录 | 管理登录会话是否过期、当前平台 | 按登录入口恢复，回来核对原账户和会话 |
| 提示会话归属不明 | 该会话是否已有内容、原平台/账户 | 等待身份确认；不要绕过只读保护 |
| 群聊发送结果不确定 | 原发送记录是否已送达 | 使用原记录重试，不再创建重复消息 |
| 子任务失败 | 胶囊中的具体任务及原会话 | 查看原因；回到会话审核草稿后重试 |
| MCP 授权后仍不能用 | 连接状态、工具发现、授权是否完成 | 使用原连接卡片重试或重新授权 |
| 上下文分类不完整 | 当前统计是否仍更新、是否为估算 | 区分占用估算与实际计费，不据此判断零费用 |

## 当前会话恢复模型

在模型恢复入口中，先选择候选模型，再点击“应用到当前会话”。选择暂存期间不会自动发出消息，也不会把它保存成所有新会话的默认模型。

只有绑定成功、运行服务就绪且账户/平台匹配后才能发送。同账户的身份查询暂未完成或失败时，应等待或恢复查询，不把它误显示成其他账户；这也不意味着应提前放开发送。

空白未归属会话只有满足保护条件时才能显式恢复。非空历史会话不会自动认领，避免旧内容或凭据跨账号使用。

## 重启前先确认

重启可能中断正在执行的本地任务和临时子智能体。先查看工具是否已经写入文件、发送请求或扣费，避免恢复后重复操作。

分别确认要重启的是桌面窗口、本地运行服务、远程网关还是第三方 MCP。只重启窗口不一定更新 Python 服务；只重启服务也不会替你更新已安装的桌面包。

界面版本可在“关于”查看。线上 API 是否已部署某提交，需要服务器或部署平台证据，不能从本地源码版本推断。

## 收集诊断信息

报告问题时提供：大致时间、桌面版本、系统、当前入口、复现步骤，以及已遮罩的错误文案或截图。能复制纯文本时优先保留原始错误信息。

不要发送密码、完整 API Key、设备 Key、登录令牌、包含秘密值的环境文件或未经遮罩的请求头。截图中也应隐藏账户和敏感内容。

已有 CLI 可在正确运行配置中使用 `hermes doctor` 检查环境；先阅读检查结果，再决定是否使用会修改状态的修复项。命令看不到桌面配置时先核对工作区，不要立刻初始化新配置覆盖它。

## 已下线的云端同步

当前版本不提供会话云同步、上传重试、跨设备自动恢复或旧云数据迁移入口。不要用“等待云同步完成”排查本地模型、登录或会话问题。

重要本地产物通过自己的文件备份保存；本地历史管理和文件导出与已下线的云同步模块无关。

## 旧会话仍使用旧名字或规则

先区分历史消息文本、缓存系统提示和自定义个性。新版本不会逐字改写已有历史，也不会覆盖用户自定义个性。确需让旧会话加载当前系统提示来源时，按[旧会话提示刷新](prompt-refresh.md)执行受控刷新。

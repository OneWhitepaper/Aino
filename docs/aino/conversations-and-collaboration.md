# 会话与协作

[返回帮助首页](README.md)

## 选择合适的会话

| 类型 | 用途 | 配置和结果归属 |
| --- | --- | --- |
| 普通会话 | 独立的问答、文件处理或项目任务 | 当前会话及所属工作区 |
| Bot 会话 | 与有固定个性、模型和工具配置的机器人长期交流 | 对应 Bot 的独立配置 |
| 群聊 | 多个成员围绕共同目标协作 | 原群聊及各成员自己的执行权限 |
| 子智能体 | 执行主任务临时委派的子任务 | 原会话；完成结果回到原任务 |

Bot 的默认聊天是它的固定入口，不会因为某次另建普通会话而被替换。机器人名称和头像用于区分成员；历史回复按当前机器人名称展示，内部 ID 不是用户识别成员的主要方式。

## 创建机器人时继承模型

新建机器人的“继承”以所选来源中已保存的默认配置为准。Aino 内置模型会继承当前账户下保存的模型选择；服务商和自定义 API 模型会继承对应模型、服务地址，并按共享账号选项使用授权。开启共享时继续使用默认工作区的共享授权池，关闭共享时复制所选来源中可复制的凭据。没有可用授权时需要补齐配置，不会从承载创建请求的另一个工作区借用密钥。

这是一份创建时的配置副本。创建后修改来源机器人的默认模型，不会自动改写已经创建的机器人；某次会话中临时切换的模型也不会成为继承来源。

打开能力或 MCP 配置可能提前创建草稿。之后修改模型会在最终创建时保存，保留草稿中的能力配置。更换继承来源、共享账号或空技能选项需要重建草稿时，界面会先说明影响并让你确认；取消或删除失败会保留原草稿。模型保存失败或取消模型确认时，不会发送首次介绍消息。

## 当前会话的模型与机器人默认模型

在会话中切换模型用于当前任务。需要长期改变机器人的默认模型时，应明确修改其配置，不要把一次群聊中的临时要求当作永久默认。

选择模型时优先使用账户可用的内置模型或已配置模型。名字相似的服务商模型不代表该服务商已配置；模型不可用时按恢复入口选择，再明确应用到当前会话。

## 协作胶囊

当普通会话、Bot 或群聊确实委派子智能体后，顶部显示协作胶囊。它是现有子任务生命周期的展示入口，不是另一个机器人或独立调度器。

1. 收起时显示正在协作的助手数量或需要关注的任务。
2. 点击胶囊，按来源会话查看任务分组。
3. 展开某项任务，查看目标、实时活动、最近事件、文件信息及可用的执行记录。
4. 点击“查看会话”回到来源会话；原会话草稿保持在自己的范围内。
5. 对可控制的任务，可按界面提供“追加指令”或“停止此任务”。

某项失败时，其他任务可以继续执行。“回到会话重试”把原任务放进来源会话的草稿，审核后发送；它不会替你自动发送新的请求。群聊的控制通过原群聊提供，不绕过群聊直接控制隐藏成员会话。

胶囊会在工作完成或需要处理时给出结果状态；关闭完成提示不删除会话或产物。离线、连接不匹配或没有操作权限时，先回到对应工作区恢复连接。

子智能体通常依赖当前运行进程，关闭其运行服务可能中断工作。需要定时、持续运行的任务请参见[调度与网关](scheduling-and-gateway.md)。

## 群聊的执行边界

当前群聊由运行网关维护会话日志和成员任务。桌面关闭后能否继续执行，取决于网关/驱动是否仍在运行、成员凭据是否有效，不是由聊天窗口是否可见决定。

群聊只显示当前服务报告支持的发送、停止、重试、审批等操作。不能假定所有群聊都支持同一套成员编辑或执行控制。成员之间不借用彼此的账户或模型凭据。

遇到发送结果不确定时，优先使用原消息的重试入口，避免再发一条新消息造成重复任务。同一个任务的重试、取消或丢弃绑定其实际执行记录；旧审批卡片不能批准新的操作。

旧版群聊历史保留阅读能力，不会因为新执行服务不可用就自动退回旧的页面执行逻辑。远程成员发来的本地路径属于对方机器，不能按本机同名文件打开。

## 停止、继续与副作用

停止只针对正在执行的任务，不撤销已发生的外部操作。界面提供继续或恢复时，沿原任务恢复，并先核对已经执行的部分；需要额外指令时在原会话说明，不把失败提示当作所有工作都未开始。

普通会话、群聊和子智能体的生命周期不同，以当前显示的可用操作为准。连接错误、模型权限不足和用户主动停止应分别处理，参见[故障恢复](troubleshooting.md)。
